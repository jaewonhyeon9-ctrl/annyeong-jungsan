## 원인 분석

### 이슈 1 — 삭제 차단의 근본 원인
DB 스키마 `supabase/schema.sql:43`:
```sql
center_id uuid references public.centers(id) on delete restrict
```
`profiles.center_id` 의 `ON DELETE RESTRICT` 때문에, 원장 계정을 **정지(active=false)** 만 해도
`center_id` 컬럼 값은 그대로 남아있어 외래키 제약이 삭제를 막음.
즉 "정지 = 삭제" 가 아니라 "정지 = 비활성", 데이터는 그대로.

### 이슈 2 — UI 라벨 혼동
`page.tsx` 가 `active` 한 컬럼만 보고 두 상태를 같은 모양으로 표시:
- 자가 가입 직후 (active=false) → "⏳ 승인 대기" + "✓ 승인하기"
- 관리자가 정지 (active=false) → 같은 "⏳ 승인 대기" + "✓ 승인하기"

사용자 의도(정지)와 UI 표시(승인 대기)가 어긋남.

## 적용한 변경

### 1) 지점 강제 삭제 API — `src/app/api/centers/[id]/route.ts` (신규)
- `DELETE /api/centers/:id` — 본문 `{ password }`
- 흐름:
  1. 호출자가 admin인지 쿠키 세션으로 확인
  2. 별도 anon 클라이언트로 `signInWithPassword(email, password)` 하여 본인 비밀번호 재검증
  3. `service_role` 권한으로 이 센터에 배정된 모든 프로필을 `auth.admin.deleteUser` (본인 제외)
  4. 센터 row 삭제 — 환자/방문/매출/유입/정산규칙 등은 ON DELETE CASCADE 로 자동 정리

### 2) 페이지 변경 — `src/app/admin/centers/page.tsx`
- `handleDeleteCenter` 흐름 교체:
  - 모드 분기 (`isSupabaseActive`): Supabase는 새 API + 비밀번호, mock 모드는 기존 `data.centers.delete()`
  - "원장이 있어 삭제 불가" 사전 차단 제거 — 강제 삭제 안내문으로 대체
- 원장 상태 라벨 통일:
  - "⏳ 승인 대기" → "🚫 정지됨"
  - "✓ 승인하기" → "✓ 활성화"
  - "정지하기" → "🚫 정지하기" (붉은 톤)
